# 磨料试配签发与页发布

岑砾道料的 8 人小组过去用打印稿追踪三条道砟筛配配方。断电后无法从旧纸面判断生效版，重试容易耗掉仅剩的页空间，留档配方页也可能被过早覆盖。上游是筛配试验员提交的粗料与细料基点，下游是生产签发主管。基点总和固定为 10000。

13:00 留存 BR-051–053 基准；13:10 将 BR-051 细料调至 2700 基点、BR-052 调至 3200；13:15 在影子页刷盘后、换根前模拟断电；13:20 复启保持旧根并重试；13:25 BR-053 改到 3100 时触发 5 页预算；13:30 解封基准；13:35 再试成功；13:40 导出新根配方和复用证据。

每张配方映射到独立物理页。写时复制为改动配方分配未引用页，根发布成功后，能回收未被当前根或封存根引用的旧页。演练将根指针切换视为原子动作，无 WAL 重做、持久存储刷盘或 PostgreSQL 内核修改；数据库保存输入、任务和回执。页数统计不含根元数据。

## 编号归属（换号）与接单

页池只保存不可变的配方内容；「编号 -> 物理页」的归属由独立的编号登记簿（`domain/ledger.py`）维护并留存完整历史，接单/换号的归属判断一律以发生那一刻的登记簿状态为准。

- `renumber` 换号：新号先与旧号绑定同一物理页（停用前的共存窗口，两号同配方、生效根只占一页、不分配新页），再整体停用旧号；任一步非法则整组回滚，登记簿原样。
- `reassign` 改派：已停用编号可以重新绑定到另一张有效配方的物理页。
- `intake` 接单：逐行解析编号并快照全量归属。同一批次里同一编号出现不同配比，或编号已停用/未登记，整批退回，页池与登记簿原样不动；同号同配比的重复行视为一致，允许接单。
- `apply_order` 执行已接订单：按接单快照定位物理页，即使原填编号此后停用或改派，改的仍是接单时归属的那张配方；已执行订单重跑为幂等无操作，不改换归属、不产生新页。
- 写时复制换页时，原页上的全部有效编号（含新旧号别名）一起迁到新页；解封基准只回收未被当前根或封存根引用的物理页，根指针不会悬空。

可见配方根证据包含三部分：步骤明细、编号归属登记簿（每个编号的绑定/停用历史、发生根次与当前状态）、接单留痕（原填编号、接单时归属页、实际改的配方页与执行根次）。

## 事件类型

| op | 含义 | 关键字段 |
|---|---|---|
| `revise` | 修订配方，按 `phase` 模拟断电三阶段 | `phase`：volatile/flushed/published，`changes` |
| `renumber` | 换号，新旧号同页后停用旧号 | `pairs`：`old_code`/`new_code` 列表 |
| `reassign` | 停用编号改派给另一张配方 | `code`、`to_code` |
| `intake` | 接单并快照归属，冲突整批退回 | `order_id`、`lines`（允许同号多行） |
| `apply_order` | 按接单快照执行订单，重跑幂等 | `order_id` |
| `release_baseline` | 解封基准、回收孤儿页 | 无 |
